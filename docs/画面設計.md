# きたねこ LP画面設計

作成日：2026年10月21日

## 設計の対象

LP制作計画に基づくPC・スマートフォンのワイヤーフレーム。情報の順序、写真と文章の面積、ボタンとページ内導線、モーションの役割を確認する。

色は構造を確認しやすい無彩色を基本とし、実写真も仮にモノクロ表示している。最終の色、写真補正、フォント、生成ヒーロー画像は次のデザイン工程で整える。

対話内の画面は「PC配置」「スマートフォン配置」を切り替えられ、「設計・動きの注記」の表示と「ページ全体」の展開ができる。

## 基準寸法

| 項目 | PC | スマートフォン |
| --- | --- | --- |
| 本制作の基準幅 | 1440px | 390px、320pxから検証 |
| 本文最大幅 | 約1240px | 画面幅に追従 |
| 外側余白 | 画面幅の約6% | 基本24px、狭幅で20px程度 |
| セクション間隔 | 90〜140px | 64〜88px |
| 本文 | 17〜18pxを想定 | 16px以上 |
| ボタンの高さ | 52px前後 | 48〜52px以上 |

対話内のPC配置は表示領域に合わせた確認用レイアウト。文字を小さく縮小した画像ではなく、読めるHTMLのまま表示する。狭い表示領域では自動的に縦配置を優先する。

## H01 ヘッダーとヒーロー

PC：ヘッダーに団体名、地域、5つのページ内メニューを配置。本文は左43%にコピーと導線、右57%に大きな写真枠。写真の左上に丸みを持たせ、施設ロゴの窓の形とつながる構図にする。

スマートフォン：団体名と開閉メニュー。本文はコピー、写真、相談ボタン、猫紹介へのリンクの順に積む。写真をPCと同じ比率で縮小せず、画面内で顔と操作が早めに見える比率にする。

画像枠は生成予定の写真の配置指示であり、最終画像ではない。猫の顔は右寄り、視線は左、柔らかい窓辺。PCの枠は縦方向に余裕を持たせるため、生成時は最終の枠と合わせてトリミング範囲を確認する。スマートフォンの表示枠は4:3を初期案とし、4:5の生成原画から安全に切り出せるか確認する。

主ボタンは来訪案内へ移動し、予約方法と条件を読んでから相談できる。副リンクは猫紹介へ移動する。

M01：写真1.025倍から等倍、見出しは行ごとに短く表示。ボタンを利用可能にしたまま約1秒以内で整う。PCのみ画像内の小さな視差を検討する。

## N01 来訪のお知らせ

ヒーロー直下に予約制であることと、最新の営業・開催情報への導線。営業情報の更新日も最終版に設ける。PCは横一列、スマートフォンは縦の3段。現在の日時は未確定なので、ワイヤーフレームで確定値として表示しない。

## C01 猫紹介

PC：導入文を左約30%、写真群を右側。紹介枠Aを縦長で大きくし、B・Cを右に上下で配置。Aの上端をずらし、ヒーローの大きな面から小さなポートレートへ視線が流れる構図。

スマートフォン：見出しと導入、Aを大きく、B・Cを2列。横スワイプが必須になる一覧にはしない。写真の直下に紹介文を置き、猫と説明の対応を崩さない。

仮配置の実写真はA `cat07.jpg`、B `cat010.jpg`、C `cat014.jpg`。個体情報は未確定なので名前や性格は創作せず「紹介枠」としている。募集中というラベルも付けていない。

M02：各写真と説明を視界に入る順に表示。初期CSSで全本文を隠す設計にはしない。最新募集一覧へのリンクは最終版でハグーへつなぐ。

## A01 活動

PC：理念を左、TNR・保護とケア・譲渡を右。右の3項目は罫線でつなぎ、写真の多い前章から文章へ切り替える。

スマートフォン：理念の後に3項目を縦に配置。写真が提供される場合は、別途実写真を1点追加できる余地を残す。

## R01 保護猫ルーム

PC：左52%に施設実写真、右に既存の施設ロゴ、説明、来訪へのリンク。団体名と施設名の違いが自然に分かる順序。

スマートフォン：施設名・説明を先に読み、その下に実写真。内観写真がなければ、既存の猫写真と文章で構成し直す。生成した内観を実施設の写真として配置しない。

## F01 家族になるまで

PC：左に導入、右に4つの手順。相談・お見合い、住環境確認、迎える準備、契約・お届け。

スマートフォン：導入の下に4つの手順。各番号と本文をつなぐ縦線を残し、流れを追いやすくする。

M03：PCでは縦線をスクロールと同期して描画する。長い画面固定は設けない。トライアル等の未確認工程は追加しない。

## D01 条件と費用

住居・室内飼育・家族の同意・対象地域などの重要情報と費用合計を常時表示。条件全文と費用内訳は開閉式。年齢条件の資料と公式サイトの相違は公開前に解消する。

費用39,000円は資料に基づく仮値として表示。ワイヤーフレームでは適用条件・追加負担が要確認であることも添える。合計額を開閉の中だけに置かない。

## S01 支援

PC：左にメッセージ、右に寄付・物資・ボランティア・一時預かりの行。スマートフォンは順に積む。

ワイヤーフレームは開閉で各枠の内容を確認できる。最終版は確定した受付先に進む行リンクへ置き換える。受け付けていない支援や架空の寄付先は掲載しない。

## Q01 FAQ

PC：見出しを左、質問を右。スマートフォンは縦に配置。予約、年齢・単身者、来訪時の持ち物を初期候補とし、回答確定後に更新する。開閉ボタンはキーボードでも利用できる。

## V01 来訪と相談

PC：左に住所・交通・営業・地図、右に予約相談の枠。スマートフォンは住所案内の後に相談枠。最後の主ボタンが、実際の受付方法へ進む出口となる。

ワイヤーフレームの地図・予約ボタンは接続先を説明するだけのローカル動作。公開前に電話番号、フォーム、受付時間、営業日時を確定し、実際の導線へ置き換える。

## スマートフォンの固定導線

来訪案内・猫紹介の2ボタン。実装時はヒーローを通過してから表示し、最後の相談枠が見えたら隠す。端末のセーフエリアと本文下の余白を確保する。対話内のプレビューでは表示領域に応じて近似するため、最終挙動は本実装で実機確認する。

## デザイン工程へ進む際の判断

1. ヒーローの写真面積、コピーの改行、主ボタンが自然に見つかるか。
2. 猫紹介の大小3枚の構図と、スマートフォンの1枚＋2枚の配置。
3. 活動から条件・費用まで読み進められる情報量と余白。
4. 支援と来訪相談の2種類の行動が混同されないか。

この構造から、生成ヒーロー画像、青緑と温かい白の配色、明朝見出しとゴシック本文を使ったデザインへ進む。
